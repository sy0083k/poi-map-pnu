# UI/UX Improvement Proposals

프로젝트: 관심 필지 지도 (POI Map PNU)  
작성일: 2026-04-10  
최종 수정일: 2026-04-10

## 문서 목적과 지위
- 이 문서는 `docs/design-reference-nsw.md`의 NSW Design System 참고 기준을 현재 웹앱 UI에 적용했을 때의 개선 후보를 정리한다.
- 현행 강제 규칙(Source of Truth)은 `docs/engineering-guidelines.md`이며, 이 문서는 구현 백로그를 선별하기 위한 제안 자료이다.
- 모든 개선은 현재 지도 런타임 분리(`/siyu` MapLibre, `/file2map`·`/photo2map` OpenLayers)와 `frontend/src/map.ts` 오케스트레이션 + `frontend/src/map/*` 모듈 구조를 유지하는 전제로 검토한다.
- NSW 브랜드 자산, 전체 CSS, `window.NSW.initSite()` 직접 도입은 제안 범위에 포함하지 않는다.

## 높은 우선순위

### 1. 검색 결과 요약 바 추가
- 근거: `Results bar`, `Search and Filters` 참고 후보.
- 현재는 결과 목록 영역과 `#nav-info`가 있지만, 사용자가 현재 어떤 조건으로 몇 건을 보고 있는지 한눈에 보기 어렵다.
- 제안:
  - 사이드바 목록 상단에 `검색 결과 N건`, 적용된 필터 chip, `조건 초기화`, `다운로드` 상태를 모은 결과 요약 바를 추가한다.
  - `/siyu`와 `/file2map`에 우선 적용한다.
- 기대 효과:
  - 검색 실행 후 맥락 보존.
  - 다운로드 대상 오해 감소.

### 2. 상태 메시지 체계 개선
- 근거: `Status labels`, `In-page alert` 참고 후보.
- 현재 `frontend/src/map/feedback.ts`는 메시지 색상을 직접 주입하고, `#map-status-text`는 한 줄 말줄임 처리된다.
- 제안:
  - 상태를 `info`, `success`, `warning`, `error` variant로 표준화한다.
  - 색상 외 텍스트 라벨 또는 아이콘성 문구를 함께 제공한다.
  - 장문 오류나 재산관리관 다중 검출 메시지는 1줄 ellipsis 대신 최대 2~3줄 확장 또는 자세히 보기 패턴을 둔다.
  - 오류성 메시지는 필요 시 `role="alert"` 또는 별도 assertive live region을 검토한다.
- 기대 효과:
  - 색상 의존 감소.
  - 접근성 향상.
  - 긴 운영 메시지 전달력 개선.

### 3. 필터 입력 접근성 보강
- 근거: `Forms`, `Search and Filters` 참고 후보.
- 현재 필터 label은 명시적 `for` 연결이 부족하고, 면적 최소/최대 입력은 placeholder 의존도가 높다.
- 제안:
  - 모든 label에 `for`/`id` 연결을 추가한다.
  - 면적 최소/최대 입력에는 각각 스크린리더용 label을 둔다.
  - `fieldset`/`legend`로 `면적`, `필터 조건`, `업로드 작업` 그룹을 의미적으로 묶는다.
- 기대 효과:
  - 키보드와 스크린리더 사용자가 조건 입력 구조를 더 쉽게 이해한다.

### 4. 업로드 흐름 안내 강화
- 근거: `File upload`, `Forms`, `In-page alert` 참고 후보.
- 현재 `/file2map`은 업로드 상태를 지도 상태바에 표시하는 정책이 있고, 업로드 패널 자체에는 파일 요구사항과 검증 실패 원인 안내가 부족하다.
- 제안:
  - 업로드 패널 가까이에 지원 형식, 필수 컬럼, 최대 용량/행 수, 선택된 파일명을 짧게 표시한다.
  - 처리 진행/실패/성공은 기존 `#map-status`와 연동한다.
  - `/photo2map`도 JPEG와 GPS EXIF 조건을 업로드 컨트롤 가까이에 유지한다.
- 기대 효과:
  - 업로드 실패 전 사용자가 요구사항을 예측할 수 있다.
  - 실패 메시지의 위치와 원인을 더 쉽게 연결할 수 있다.

## 중간 우선순위

### 5. 상세 정보 패널의 정보 구조 개선
- 근거: `Data visualisation`, `Tables`, `Content blocks` 참고 후보.
- 현재 상세 패널은 2열 key/value 그리드로 구성되어 있지만, 동적 필드가 많아지면 중요 정보와 원본 컬럼이 섞일 수 있다.
- 제안:
  - 핵심 필드(PNU, 주소, 지목, 면적, 관리관)를 상단 summary로 고정한다.
  - 원본 컬럼은 접을 수 있는 `전체 속성` 영역으로 분리한다.
- 기대 효과:
  - 지도 클릭 후 즉시 판단해야 하는 정보가 먼저 보인다.

### 6. 목록 항목을 버튼/선택 상태 중심으로 개선
- 근거: `List items`, `Accessibility` 참고 후보.
- 현재 가상화된 목록 항목은 `div.list-item`에 click listener를 붙이는 구조이다.
- 제안:
  - 가상화 구조는 유지하되 각 row를 `button` 또는 `role="button"` + `tabindex` + `aria-selected`가 있는 선택 가능한 항목으로 만든다.
  - 선택된 항목에는 색상뿐 아니라 border/text label 등 비색상 단서를 둔다.
- 기대 효과:
  - 키보드 탐색과 선택 상태 전달이 좋아진다.

### 7. 관리자 화면의 폼/상태 패턴 정리
- 근거: `Forms`, `Tables`, `Status labels`, `In-page alert` 참고 후보.
- 현재 관리자 화면은 인라인 CSS가 많고, 상태 영역도 id별 텍스트 갱신에 의존한다.
- 제안:
  - 관리자 폼에 공통 field/help/error/status 스타일을 정의한다.
  - 업로드, 설정, 비밀번호 변경 결과를 같은 alert/status 컴포넌트 체계로 통일한다.
  - `재시작 필요` 배지는 실제 hot-reload 가능 설정과 불가능 설정을 구분해서 표시한다.
- 기대 효과:
  - 운영자가 어떤 변경이 즉시 반영되는지 덜 헷갈린다.
  - 관리자 화면의 오류/성공 피드백이 일관된다.

### 8. 범례와 색상 의미의 접근성 보강
- 근거: `Data visualisation`, `Status labels`, 접근성 체크리스트.
- 현재 범례는 관리관별 색 swatch가 있고, 지도 하이라이트도 색상 의미가 크다.
- 제안:
  - 범례 swatch에 패턴, 테두리, 텍스트 보조를 더한다.
  - 색 대비를 점검하고, 색각 이상 사용자를 고려해 색상 단독 의존을 줄인다.
  - 선택 상태는 기존 halo/pulse와 `prefers-reduced-motion` 대체 스타일을 유지한다.
- 기대 효과:
  - 지도 데이터 해석 안정성이 올라간다.

## 낮은 우선순위

### 9. 토스트와 상태바 역할 분리
- 근거: 상태 메시지와 alert 역할 분리 원칙.
- 현재 `#ui-toast`와 `#map-status`가 모두 상태 전달을 담당한다.
- 제안:
  - 토스트는 짧은 완료, 복사, 선택 피드백에 사용한다.
  - 상태바는 작업 진행, 검증, 오류, 결과 요약에 사용한다.
  - 코드와 문서에서 두 역할을 명시한다.

### 10. 시각 토큰 정리
- 근거: 컴포넌트 일관성, 긴 콘텐츠 내구성, 디자인 시스템 참고 원칙.
- 현재 버튼, 패널, alert, focus outline 색상이 여러 위치에 직접 정의되어 있다.
- 제안:
  - `static/css/style.css` 상단에 색상, 간격, 반경, 상태 토큰을 정리한다.
  - 관리자 인라인 CSS와 지도 CSS의 공통값을 점진적으로 맞춘다.
  - NSW 색상 자체를 복제하지 않고 이 앱의 색 체계를 유지한다.

## 권장 진행 순서
1. 상태 메시지 variant와 결과 요약 바를 먼저 설계한다.
2. 필터 label/fieldset과 목록 항목 키보드 접근성을 보강한다.
3. 업로드 안내와 관리자 alert/status 체계를 통일한다.
4. 상세 패널 정보 구조와 범례 접근성을 개선한다.
5. 마지막으로 CSS 토큰 정리를 하되, 대규모 리스킨은 피한다.

## 검증 기준
- 데스크톱과 모바일에서 `/siyu`, `/file2map`, `/photo2map`의 검색, 선택, 상세 패널, 업로드 흐름을 수동 확인한다.
- 키보드만으로 필터 입력, 검색 실행, 목록 선택, 패널 닫기, 메뉴 조작이 가능한지 확인한다.
- 색상만 제거하거나 구분이 어려운 환경에서도 상태와 선택 의미가 전달되는지 확인한다.
- 구현 변경 시 `cd frontend && npm run typecheck && npm run build`를 실행한다.
- 관련 UI 계약이 바뀌면 `tests/test_map_ui_contract.py`와 `tests/test_map_ui_contract_static.py`를 함께 갱신한다.

## 잔여 리스크
- 실제 화면 캡처 기반 접근성 검증은 별도 구현 단계에서 수행해야 한다.
- `nsw-design-system` npm 패키지 직접 도입은 이 문서의 개선 후보에 포함하지 않는다.
- 패키지 도입이 필요해질 경우 `docs/design-reference-nsw.md`의 도입 검토 절차를 먼저 따른다.
